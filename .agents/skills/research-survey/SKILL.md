# 论文调研

在本仓库中使用；先读取 `docs/protocol.md` 和 run 的 `brief.md`、`state.json`。没有课题时先询问课题，不生成虚构示范结果。

将课题拆成研究问题、近义术语、方法和应用边界，构建英文为主、必要时中文补充的查询式。按学科选择可用的学术搜索、数据库、会议/出版社页面、作者项目页；不要限定所有领域必须使用同一数据库。记录真实访问日期、查询式和筛选依据。若某个平台不可用，说明覆盖缺口并利用可用来源继续。

先检索综述和代表性工作形成路线，再补近期进展及向前/向后引用追踪。优先实际打开论文官方页核验标题、年份和版本，能读到摘要或全文则记录材料级别。网页摘录不能自动等同于全文。

候选数量随课题范围调整，通常先形成 10–20 篇足以讨论的列表，若证据不足就少列。选取能代表不同路线和关键进展的文章，不以数量充足或高引用量代替相关性。去除同篇版本重复，保留有价值的排除理由。为每篇给出稳定 ID、问题、核心思路、课题关联与具体精读理由。

保存 `search-log.md`，按协议生成候选 JSON，并执行 `python scripts/workflow.py import <run> --papers <candidate-json>`。脚本重复检查报错时核对版本，不能通过改 ID 绕过去重。对已开始精读的课题补搜，使用新一轮 run 并链接旧记录。

调研完成后交给 `../research-briefing/SKILL.md`。此阶段不因候选推荐而自动开展深入方法推导、完整精读或制作最终 PPT。
