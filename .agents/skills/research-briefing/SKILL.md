# 向用户介绍并选文

读取本仓库 `docs/protocol.md`、run 的 `brief.md`、`papers.json`、`search-log.md`。先说明该领域在解决什么问题，再介绍主要路线、路线间区别和当前争议，帮助非专门读者理解为什么这些论文值得看。

在 `briefing.md` 保存导读，并在聊天中实际介绍，不能只扔给用户文件路径。初次讲解通常 5–10 分钟可读完，随用户知识背景调整。内容包括：

- 关键概念及研究问题，避免无关教材背景。
- 主要技术路线及关系，可用有内容的简图或对照表。
- 候选短介绍：ID、标题与年份、解决什么、基本思路、为什么值得读、初筛材料级别。
- 推荐精读的具体组合及理由，例如奠基、代表方法、近期改进、相反证据。推荐数量随主题和阅读预算调整。

没有读全文的论文，关于贡献和局限只陈述现有材料能支持的判断。不要把关键词匹配说成经过精读后的结论。

完成讲解后执行 `python scripts/workflow.py brief <run> --file briefing.md`。然后邀请用户用编号、标题或明确条件选文，例如“精读 P002 和 P006，重点看实验设计”。可以给推荐组合供选择，但不默认选中。

用户询问比较或要求补搜时先回答或补搜。用户作出可明确解析的决定后，将真实原话和解析出的 ID 传给 `select`。不能将自己的推荐文字填入 `--user-message` 冒充用户决定。选文前停止在这一阶段，选文后交给 `../research-reading/SKILL.md`。
