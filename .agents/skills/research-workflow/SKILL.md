# 科研工作流

定位本技能所在仓库根目录，读取 `docs/protocol.md`。所有代码路径相对于该根目录；实际课题资料保存在 `runs/<topic-slug>/`。不要将用户课题直接作为未经处理的 shell 代码或路径片段。

## 开始或恢复

先找用户指定的已有 run。只有一个相关 run 时用 `python scripts/workflow.py status <run>` 恢复；多个匹配时用课题和时间帮助用户定位。没有 run 时初始化，并将已知需求写入 `brief.md`。用户尚未提供研究主题时询问主题，其余默认中文、近三年加必要经典、组会约 15 分钟，允许用户修改。不要把一次任务变成冗长问卷。

按状态读取一个所需技能，技能目录与本技能同级：

| 状态 | 执行 |
| --- | --- |
| collecting | `../research-survey/SKILL.md` 检索后，用 `../research-briefing/SKILL.md` 向用户介绍 |
| awaiting_selection | 回答用户对候选文献的问题，等待用户明确选文 |
| reading | `../research-reading/SKILL.md` |
| ready_for_slides | `../research-slides/SKILL.md` |
| complete | 给出产物链接；按用户要求继续修改 |

必须在导读后给用户选择机会。推荐列表不等于已选列表。用户可以指定 ID、标题、可明确解析的条件，也可以明确授权 AI 代选；记录真实原话与对应 ID 后调用 `select`。歧义会改变精读范围时，只澄清该歧义。不得因为时间经过、用户沉默或 AI 自己的推荐而继续精读。

选文后自动推进精读、综合和 PPT，无需重复请求已授予的授权。全文缺失只阻塞相关文章；先处理其他所选论文，再向用户说明获取全文或调整选择所需的信息。用户只要求其中一个阶段时，按该范围交付。

## 状态与交付

使用 `scripts/workflow.py` 修改状态；用 `--help` 查看参数。每个阶段保留证据文件。用户改变选择后重新登记已核对的笔记，避免沿用过期状态。依赖工具失败时保存成果、标明尚未完成的步骤；不能用空文件或虚构引用推动状态。

源代码上传授权不包含自动发布调研材料。默认仅保存在 run 内。最终回复给出 PPT 和精读笔记的实际链接，以及影响使用的缺失项。
